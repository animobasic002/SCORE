Understanding your result

This is a short synthetic benchmark, not a complete hardware diagnosis. It temporarily increases CPU usage and may cause fan noise or warmth. Stop testing if your device becomes uncomfortable.

How the score works

Each workload receives a short warm-up before measurement. Single-worker CPU runs for 2.5 seconds, parallel CPU for 3.5 seconds, and memory copy for 2.5 seconds.

The score uses a weighted geometric mean: 35% single-worker CPU, 45% parallel CPU, and 20% memory copy. Arbitrary reference rates are 20 million CPU iterations/second, 80 million parallel iterations/second, and 5 GB/second memory copy. A machine exactly matching those rates scores 1,000.

These references are scaling constants—not measured reference hardware or population averages. Twice the score means twice the weighted normalized throughput in these workloads, not twice the performance in every application.

Compare results using the same browser version, selected worker count, power mode, and benchmark version. Repeat runs to check consistency. Worker count defaults to reported logical concurrency, capped at 16 to avoid excessive resource use.

JavaScript engine optimizations, scheduling, CPU caches, thermal limits, and background activity affect results. Memory results include cache and browser effects; they are not raw DRAM bandwidth. GPU, disk, network, temperatures, and hardware health are not tested.

Everything executes on this device. Exported reports include browser identification and benchmark results, but are never uploaded.
